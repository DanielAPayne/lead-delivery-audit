# lead-delivery-audit

Matching totals can hide lost leads. If 100 forms were submitted on Meta and HubSpot shows 100 new rows, three leads may still be missing while three others were written twice.

`lda` traces each paid lead through three stages by its submission ID: the ad form (source), the automation such as n8n or Zapier (router), and the CRM. For each lead that did not arrive exactly once, it reports the last stage that recorded it. It runs locally on exported files. Nothing is uploaded, and contact details are discarded when the files are read.

**In a browser:** https://danielapayne.github.io/lead-delivery-audit/ (one self-contained file, [`docs/index.html`](docs/index.html); save it and it works offline). Drop in the exports, or try a synthetic example. Its content security policy blocks all network requests.

**On the command line:**

```bash
npx github:DanielAPayne/lead-delivery-audit example exceptions
```

## What it reports

| Finding | Meaning | Next check |
|---|---|---|
| Present at source only | The form recorded it; the router never did | Source-to-router handoff: trigger, form scope, connection |
| Seen by router, no CRM receipt | The automation ran; the CRM has no row with this ID | That router run, destination errors, routing filters |
| No CRM receipt | No router export was given, so the break is not located | Add router logs |
| Repeated in CRM | More than one CRM row carries this ID | Retried write or repeated logging |
| Unresolved | Some CRM rows carry no submission ID, so absence proves nothing | Map an event-level ID into the CRM, then rerun |

It also lists CRM IDs that are not in the source export (other forms, outside the window, or an incomplete export) and states how many absent leads are missing for certain even when the evidence is incomplete.

Exit codes make it usable as a scheduled check: `0` clean, `10` exceptions, `11` incomplete evidence, `2` usage or input error.

## Usage

```bash
lda audit --source meta-leads.csv --router n8n-runs.csv --crm hubspot-events.csv \
  --crm-id-column "Meta Lead ID" --from 2026-10-01 --to 2026-11-01 --out report.md
```

- `--router` is optional but needed to locate a break.
- ID columns are auto-detected (`submission_id`, `lead_id`, `leadgen_id`, `Lead ID`, `id`, ...); pass `--source-id-column`, `--router-id-column` or `--crm-id-column` when they are not.
- `--from` / `--to` filter by source timestamp (from inclusive, to exclusive). Timestamps without a time zone are read as UTC and flagged in the report.
- `--format json` for machine-readable output.
- Accepts CSV, TSV, semicolon-separated and JSON Lines (`.jsonl`), in UTF-8 or UTF-16 with a byte-order mark. Meta's `l:` prefix on lead IDs is removed.

## Receipt format

Every input reduces to one receipt per row: a submission ID, an optional timestamp and a row reference. Any export works if one column carries the original form submission ID:

```csv
submission_id,observed_at
1234567890123456,2026-10-02T14:03:11Z
```

The CRM side is the hard part. A HubSpot contact is not a receipt: one contact can predate a submission or represent several. A reliable audit needs the Meta lead ID written to the CRM for each submission (a contact property, a form-submission field or a custom event). If it isn't there, the report says the evidence is incomplete instead of guessing. Adding that ID is usually the first fix.

## Examples

`examples/` holds three synthetic cases of 100 submissions each, generated by `scripts/make-examples.js`:

- `exceptions`: totals agree at 100, but 3 are missing (one lost before the router, two after it) and 3 are repeated.
- `healthy`: every ID arrives once.
- `incomplete`: 3 CRM rows have no ID, so 3 submissions stay unresolved.

Version 0.1: the engine and command line. Column names for real Meta, HubSpot, Zapier and n8n exports have not yet been checked against live files; use the column flags if auto-detection misses. Planned: an n8n recipe that carries the Meta lead ID into HubSpot, and export presets.

## Development

```bash
npm test
node scripts/build-web.js   # rebuild docs/index.html after changing src/ or web/template.html
```

The browser page is generated from `web/template.html` with `src/` and `examples/` inlined; CI fails if it is stale.

Node 20 or later, no dependencies.
